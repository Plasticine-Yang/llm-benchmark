# Reactive Spreadsheet Engine

一个可运行的全栈响应式电子表格：**手写公式引擎 + 真实依赖图 + 增量重算 + 循环引用检测 + 后端持久化**。
前端零运行时依赖（原生 ES Modules + Vite 构建），后端是 Node 内置 `http`（无 Express、无数据库），工作簿以 JSON 原子写入 `data/workbook.json`。

网格为 **30 行 × 12 列（A1:L30）**，满足 ≥20 行 ≥10 列的要求。

---

## 1. 环境与启动

需要 Node.js **18+**（本项目在 Node 22 上开发）。

```bash
cd <项目根目录>
npm install
```

### 开发模式（一条命令同时启动 API + Vite）

```bash
npm run dev
# 浏览器打开 http://localhost:5173
# Vite 把 /api 代理到 http://localhost:18787
```

### 生产模式

```bash
npm run build     # 产出 dist/
npm start         # http://localhost:18787 同时提供静态页面与 API
```

可用 `PORT=19000 npm start` 改端口（开发模式下 Vite 代理会自动读取同一环境变量）。
默认端口 18787 是为了避免与本机其它服务冲突；若该端口被占用，启动脚本会自动顺延并在控制台打印真实地址，
同时把地址写入 `data/runtime-port.json`。`npm run dev` 会先探测空闲端口，再把同一个端口同时传给 API 与
Vite 代理，因此前端始终打开 **http://localhost:5173** 即可。

初始 `data/workbook.json` 预置了一条干净的四级依赖链（A1→B1→C1→D1→E1），打开页面即可直接改 A1 验证级联；
点「清空」可从空白工作簿开始。

### 其他命令

```bash
npm test          # 11 组引擎单元测试（node:test，无额外依赖）
npm run server    # 只启动后端（配合已有 dist 使用）
```

## 2. 验收场景怎么走

1. **三级依赖链**：点击「载入示例」。示例包含
   `A1=100 → B1(=A1*2) → C1(=B1+10) → D1(=SUM(C1:C3)/2) → E1(=D1+C1)`。
   把 **A1 改成 200**，右侧「增量重算日志」会显示仅重算 `A1,B1,C1,D1,E1` 这 5 个单元格（无关单元格不动），
   紫色闪烁标记本次重算范围，B1/C1/D1/E1 依次变为 400/410/210/620。
2. **间接循环引用**：点击「演示：间接循环」，会写入
   `K1=K2+1, K2=K3+1, K3=K1+1`，形成 `K1→K2→K3→K1` 三级循环。
   K1/K2/K3 全部显示 `#CYCLE!`，依赖它们的 K4 也会传播 `#CYCLE!`；页面不会卡死。
   按 `Ctrl+Z` 即可恢复。手工验证也可以：把示例中 `C1` 改成 `=E1+1`。
3. **撤销 / 重做**：`Ctrl+Z` / `Ctrl+Y`（或工具栏按钮），保留最近 **50** 次编辑（要求 ≥20）。
   撤销会同时恢复公式的**计算结果**，不只是原始文本。
4. **刷新持久化**：任意编辑后等状态栏出现「已保存 · vN」，刷新整个页面。
   原始值、公式、计算结果都会恢复；状态栏显示「重载校验通过 ✓」——
   服务端会用**同一套引擎**独立复算一遍并与浏览器计算结果逐格比对。

- 右侧「依赖关系图」画出上游 / 下游连线，列表中的单元格可点击跳转。

## 4. 公式语言（全部自行实现）

- **词法分析** `src/engine/tokenizer.js`：数字（含小数、科学计数法）、标识符、字符串、`+ - * / ^ ( ) , :`，非法字符 → `#PARSE!`。
- **语法分析** `src/engine/parser.js`：递归下降，优先级 `^` > 一元正负 > `* /` > `+ -`，括号可任意嵌套。
- **单元格引用**：A1 风格，大小写不敏感，支持绝对引用 `$A$1` / `$A1` / `A$1`。超出网格（A1:L30）的引用 → `#REF!`。
- **范围**：`A1:B5`（可作为函数参数，也可嵌套在表达式里）。
- **函数**：`SUM`、`AVG`（别名 `AVERAGE`）、`COUNT`、`MIN`、`MAX`、`ABS`、`ROUND`。
  范围参数会忽略文本与空单元格（与 Excel 一致），但范围内的错误会向外传播。
- **组合**：`=ROUND(SUM(A1:A3)/3, 2) + MAX(B1:B5)*2 - (C1+1)` 之类完全支持。
- **前向引用**：`A1 = B1+1`，B1 尚未填写时按 0 处理；之后填写 B1 会立刻触发 A1 重算。

示例：

```
=2+3*4                      → 14
=(2+3)*4                    → 20
=SUM(A1:A5)*2 + AVG(B1:B5)  → 范围 + 函数 + 算术
=A1/(B1-2)                  → B1=2 时 #DIV/0!
=ZZ100                      → #REF!
="abc"+1                    → #VALUE!（文本用单参数算术时）
```

### 错误传播

| 错误 | 触发 |
| --- | --- |
| `#CYCLE!` | 直接 / 间接循环引用。**环上每个单元格**都显示，且不会死循环；下游单元格继续传播该错误 |
| `#DIV/0!` | 除以 0；`AVG` 空范围 |
| `#REF!` | 越界引用、越界范围、非法 A1 记号 |
| `#VALUE!` | 文本参与算术、范围当标量使用、参数个数错误 |
| `#NAME?` / `#PARSE!` / `#NUM!` | 未知函数 / 语法错误 / 数值溢出 |

任何错误作为操作数出现时都会**优先向外传播**（第一个错误胜出），因此 `=1/0+1`、`=SUM(A1:A2)`（A1 为错误）都会得到同一个错误。

## 5. 依赖图与重算算法

`src/engine/workbook.js` 维护两张表：

- `deps: 公式单元格 → 它读取的单元格集合`（解析 AST 时抽取，范围会展开成单格）
- `rdeps: 单元格 → 读取它的公式单元格集合`（反向边）

编辑流程：

1. 对被修改的单元格撤销旧边、解析新公式、建立新边。
2. 从被修改单元格出发，沿 `rdeps` 做 BFS，得到**受影响闭包**（改动格 + 所有直接/间接依赖它的公式）。只有这个闭包会被重算。
3. `src/engine/graph.js` 在受影响子图上跑 **Tarjan SCC**：
   - 大小 > 1 的强连通分量，或带自环的单点分量 → 循环，分量内所有单元格置 `#CYCLE!`。
   - 对缩点后的 DAG 做 **Kahn 拓扑排序**，保证被依赖的单元格先算、依赖它的后算；因此多级间接依赖、前向引用都按正确顺序求值。
4. 求值器通过上下文读取其它单元格的**当前结果**，错误自然向依赖链传播。

由于循环被 SCC 显式标记，求值过程不存在递归下降搜索依赖导致的无限递归，永远在有限步内结束。

`src/engine/` 是纯 ESM 模块，不依赖 DOM 或 Node API，因此**浏览器与服务端共用同一份引擎代码**。

## 6. 后端与持久化

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/workbook` | 返回 `{ cells, computed, version, updatedAt, stats }` |
| `PUT` | `/api/workbook` | 请求体 `{ "cells": { "A1": "=B1*2" } }`，原子写入 `data/workbook.json` |
| `GET` | `/api/health` | 健康检查 |

服务端每次保存都会用共享引擎对原始 cells **独立全量复算**，把 `computed` 一起落盘。
浏览器加载时同样重算一次并与服务端结果逐格比对，界面底部显示校验结果。
因此刷新后不仅原始文本和公式在，计算值也是经过双重校验的。

`data/` 目录运行时自动创建（已加入 `.gitignore`）。删除 `data/workbook.json` 即可重置为空工作簿。
